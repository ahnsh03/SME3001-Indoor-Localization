## 1.2 교육적 맥락: 성능만이 목적이 아닌 이유

지도 교수님께서는 평가 시 **최종 RMSE 숫자 자체보다, 개발 과정에서의 시행착오·통찰·그 통찰을 다음 실험에 어떻게 반영했는지**를 중요하게 보신다고 전달되었다. 이는 본 연구 목적 서술의 **1차 원칙**이다.

따라서 본 계획 보고서와 이후 `report.md`에서는 다음을 병행한다.

1. **재현 가능한 실험 기록** — 어떤 버전(V1~V15)에서 무엇을 시도했고, 검증 RMSE가 어떻게 변했는지 (`batch_rerun.log`, `*_summary.json`).
2. **실패와 기각의 이유** — 예: Pure UWB RMSE 7.11 m(V8), V14 JWT Step C 2.23 m, V16 HardGate 1.83 m 등은 “나쁜 성적”이 아니라 **가설 기각의 증거**로 기술한다.
3. **튜닝 무결성** — 검증 라벨로 하이퍼를 고른 V12(Step C 1.445 m)와 Train CV만 사용한 V15( HardGate 1.462 m)를 **동일 선상에서 비교하지 않음**을 명시한다.

즉, 기말 프로젝트에서 높은 점수를 목표로 하되, 그 점수는 **과정이 정당화된 알고리즘**에서 나와야 한다는 것이 본 연구의 태도이다.

## 1.3 중간 프로젝트에서 확인된 문제의 본질

중간 프로젝트의 목표는 “6 UWB + 6 Wi-Fi 앵커 거리로 실내 2D 위치 추정”이었다. 그러나 **실측 데이터 분석**과 **25회 파이프라인 재실행**을 통해 다음이 반복적으로 확인되었다.

### (1) UWB는 신뢰할 수 있는 1차 관측이 아니었다

`sensor_spatial_profiler` UWB 순차 필터 결과(Train, 2026-05-19 재실행):

- 1176개 long-format 레코드 → 최종 Clean **707개** (약 40% 제거).
- Clean 이후에도 거리 오차 MAE **2.83 m**, P90 **6.83 m**.
- 앵커별 체계적 bias **약 −0.8 ~ −3.6 m**.

V8 애블레이션(동일 재실행):

| 모드 | 검증 RMSE |
|------|-----------|
| Pure Wi-Fi | **1.55 m** |
| Pure UWB | **7.11 m** |
| Hybrid (HBB) | 3.51 m |

**통찰:** 실내 실측 환경에서 UWB는 “정밀 측距”가 아니라 **강한 이상치·결측·오프셋**을 동반한다. Wi-Fi 없이 UWB만으로는 측위가 성립하지 않는다.

### (2) Wi-Fi 가이드는 “한계 내 최선”이었으나 구조적 종속을 만든다

V9~V12 계열은 **Wi-Fi로 1차 좌표(가이드)를 만든 뒤 UWB를 기하 잔차 게이트로 융합**하는 구조이다. 검증 RMSE는 1.44~1.47 m대까지 개선되었으나,

- 알고리즘이 **Wi-Fi 품질에 전제**된다.
- 기말 데이터처럼 **단일 RTT 관측군(18 BS)** 만 있는 문제에는 **구조를 그대로 이전할 수 없다**.

**통찰:** “가이드 센서 + 보조 센서 게이팅”은 중간 데이터에 맞는 **응급 처방**이었지, 일반적 셀룰러 측위의 표준 형태는 아니다.

### (3) 검증 튜닝은 숫자를 낮추지만 연구 윤리상 비교 기준이 아니다

V12 기본 파이프라인은 검증 RMSE로 그리드를 택해 Step C **1.445 m**을 기록한다. 반면 V15는 Train OOF 게이트 + Train CV Optuna만으로 HardGate **1.462 m**을 얻는다. 전자가 더 낮아 보이나, **hidden·일반화 관점에서는 후자가 더 정직한 개발 경로**이다.

**통찰:** 중간 프로젝트 후반의 핵심 성과는 “0.01 m 개선”이 아니라 **무결 튜닝 절차(V12 Turbo → V13 → V15)를 코드화**한 것이다.

### (4) V15를 최종으로 둔 이유

V15(`defensive`, 2026-05-19 재실행)는 다음을 동시에 만족한다.

- v12 **검증튜닝 그리드 미import** (`integrity` 필드).
- Train K-Fold **OOF**로 UWB 게이트 τ 구간 산출 (raw [1.09, 3.95] m → defensive [1.15, 2.80] m).
- Optuna 목적: **Train CV** composite (Wi-Fi-Guide + Fusion-ReWeight).
- 검증 라벨은 **최종 1회 포워드**만.

| V15 단계 | 검증 RMSE (m) |
|----------|---------------|
| Wi-Fi-Guide | 1.574 |
| **Fusion-HardGate** | **1.462** |
| Fusion-ReWeight | 1.475 |

HardGate가 ReWeight보다 우수한 것은, 불안정 UWB에 **IRLS 재가중보다 채널 제거(게이트)** 가 낫다는 중간 프로젝트의 **최종 공학적 결론**이다.

## 1.4 기말 프로젝트에서의 문제 재정의

기말 데이터 `InF_DH_FR1.mat`(채점 시 `DH_FR1.mat`)는 다음과 같다.

- `d_hat` (18, N): 18기지국 RTT.
- `p_bs` / `BS_positions` (2, 18): 기지국 좌표.
- 학습용 `p` (2, 700): GT 위치 **제공** → **지도 학습 가능**.
- 채점 시 300명 추가 → **700명에만 overfit하면 불리**.

EDA(2026-05-19, `final_eda_stats.json`):

| 지표 | 값 |
|------|-----|
| d_true vs d_hat 상관 | 0.815 |
| 잔차 평균 (d_hat − d_true) | +15.9 m |
| Huber LS 삼변 RMSE (700명) | 19.25 m |

**해석:** 중간의 “UWB 지옥”과 달리 **합성·가공 데이터**이므로 기하 구조는 존재한다. 그러나 **전역 bias·스케일 왜곡**이 커서, naive 삼변만으로는 부족하다. 중간에서 쓰지 못했던 **학습 기반 거리 보정·잔차 모델**이 기말에서는 정당화된다.

또한 공간 범위(x 약 ±60 m)가 중간 실험실 타일(12×18 m)보다 넓어, **PHASE1 고정 bias·타일 경계 상수**는 이관하지 않는다.

## 1.5 본 연구(11주차~기말)의 목적 — 3층 구조

### 【1차 목적】 중간 개발 과정의 체계적 환류

중간 프로젝트 V1~V15·JWT에 걸친 **시행착오를 서술 가능한 형태로 고찰**하고, 그 결과를 기말 알고리즘 설계의 **가설·제약·baseline**으로 사용한다.

- **이관:** Huber/IRLS 강건 최적화, 기하 잔차 기반 BS 마스킹(게이트 개념), Train K-Fold·Optuna, 무결 평가 규약.
- **비이관:** Wi-Fi 가이드 2단계, UWB 순차 필터·PHASE1 bias, 실내 타일 전용 상수, 검증 그리드 튜닝.

이 환류는 “코드를 복사”하는 것이 아니라, **왜 그 선택을 했는지**를 `report.md`에서 설명 가능하게 만드는 것이다.

### 【2차 목적】 기말 데이터에 맞는 학습형 측위 파이프라인 설계

700명 GT를 활용해 **`train.py`에서 학습**하고, `main.py`는 학습 결과만으로 1000명 규모 추론(시간 10분 이내)을 수행하는 구조를 설계한다.

우선순위 후보:

| 안 | 개요 | 중간과의 연결 |
|----|------|----------------|
| **A (주력)** | RTT 채널 보정(학습) + Huber 삼변 + BS 마스킹 | V15 게이트·Huber의 RTT판 |
| B | End-to-end MLP: (d_hat, BS) → (x,y) | 성능 탐색용; baseline 공정성 논의 필요 |
| C | 비학습 Huber LS + CV | 공정 baseline |

**1차 목적:** 안 A의 프로토타입 + 5-fold CV RMSE.  
**2차 목적:** hidden 대비 과적합 점검 및 안 B 필요 여부 판단.

### 【3차 목적】 교과 요구사항 충족과 재현성 확보

- `final_project_discription.md` 규격: `main()` 반환 (2, num_user), `DH_FR1.mat`, 표준 패키지.
- Public repo, `report.md` 4개 필수 절(모티베이션·알고리즘·Agent AI·결과·Reference).
- 중간 repo의 `REPRO_20260519.md`처럼, 기말도 **재현 로그·고정 시드·학습/추론 분리**를 문서화한다.

## 1.6 연구 질문 (Research Questions)

본 계획 기간 및 기말 제출까지 다음 질문에 답한다.

**RQ1.** 중간 프로젝트에서 UWB가 실패하고 Wi-Fi 가이드가 성공한 **구조적 이유**는 무엇이며, 기말 RTT 단일 관측에서는 어떤 **대체 구조**(학습 보정·게이트)가 타당한가?

**RQ2.** Train 700명 내부 CV RMSE를 최소화하는 하이퍼·모델이 **과적합 없이** 합리적인 추정을 하는가? (중간에서 검증 튜닝이 만든 “가짜 개선”을 반복하지 않기 위함)

**RQ3.** 중간 V15에서 HardGate가 ReWeight보다 우수했던 현상이, 기말 **BS 마스킹 + 강건 삼변**에서도 재현되는가, 아니면 **학습 보정만으로 충분**한가?

**RQ4.** Agent AI(Cursor 등)를 **설계·구현·실험 자동화**에 어떻게 쓰고, 본인이 검증한 부분(무결성, 데이터 감사)은 무엇인가? (`report.md` §Agent AI 대비)

## 1.7 기대 성과 및 성공 기준

### 정성적 성과

- 중간 V1~V15 **진화 타임라인**을 교수님께 설명 가능한 스토리로 정리 (시각화: `fig03_midterm_evolution.png` 등).
- “실측 UWB 문제 → Wi-Fi 가이드 → 무결 V15 → 기말 학습형 전환”의 **인과**가 문서·발표에서 일관됨.

### 정량적 성과 (기말, 계획)

| 단계 | 목표 | 비고 |
|------|------|------|
| 12주 | Huber baseline + 5-fold CV 파이프라인 | RMSE 기록만, SOTA 아님 |
| 13주 | 학습 보정층 통합, `train.py`/`main.py` 분리 | `model.pt` 저장 |
| 14주 | 내부 hold-out·ablation | hidden은 직접 볼 수 없음 |

**성공의 최소 기준:** hidden 점수 극대화만이 아니라, **(1) baseline 대비 개선**, **(2) CV와 테스트 일관성**, **(3) report.md에서 과정 설명 가능**의 삼각을 만족하는 것.

### 성공의 최대 기준

- 학습 보정 + 강건 삼변 + BS 마스킹이 **단순 E2E 대비 해석 가능성·성능**에서 균형을 보임.
- 중간에서 축적한 **Optuna·K-Fold 인프라**를 기말 `train.py`에 이식하여 실험 반복 비용을 낮춤.

## 1.9 요약 (한 문단)

본 연구의 목적은, **실측 UWB 노이즈 속에서 Wi-Fi 가이드·기하 게이트·무결 튜닝으로 도달한 중간 프로젝트 V15의 개발 과정**을 체계적으로 정리하고, 그 과정에서 얻은 **강건 기하·채널 선택·정직한 CV**의 교훈을 **합성 RTT 기말 데이터**에 맞게 **학습형 측위**로 재구성하는 것이다. 최종 성능 수치는 중요하나, 교수님께서 강조하신 대로 **시행착오와 통찰을 기말 설계에 환류했는지**가 본 11주차 연구 계획의 핵심 평가 축이다. 이를 위해 2026-05-19자 중간 코드·산출물 전량 재실행으로 문서를 갱신하였고, 이후 주차에서는 `train.py` 중심의 프로토타입 실험으로 RQ1~RQ4에 답할 예정이다.
