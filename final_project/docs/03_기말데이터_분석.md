## 3.2 탐색적 데이터 분석 (EDA)

### 3.2.1 공간 배치

| | x (m) | y (m) |
|---|-------|-------|
| UE `p` | −60.0 ~ 60.0 | −29.9 ~ 29.8 |
| BS | −50 ~ 50 (20 m 간격 그리드) | −20, 0, 20 |

18개 BS는 **3×6 격자**에 가깝게 놓여 있고, UE는 그 위 영역에 고르게 분포한다. 중간 실험의 6앵커 실내 타일과 비교하면 **스케일이 약 5배 이상 크다**. 따라서 중간의 `PHASE1_UWB_BIAS_M`, 타일 경계 상수, Wi-Fi 가이드 좌표계는 **그대로 이전할 수 없다.**

### 3.2.2 RTT vs 기하 거리: 상관은 있으나 동일하지 않다

각 UE \(u\), BS \(k\)에 대해

\[
d_{\mathrm{true},k}(u) = \|\mathbf{p}_u - \mathbf{a}_k\|,\quad
\mathrm{resid}_{k}(u) = \hat{d}_k(u) - d_{\mathrm{true},k}(u)
\]

**그림 삽입:** `fig01_final_dhat_vs_dtrue.png` (산점도 + 잔차 히스토그램)

| 지표 | 값 (700 UE × 18 BS) |
|------|---------------------|
| Pearson 상관 corr(\(d_{\mathrm{true}}, \hat{d}\)) | **0.815** |
| 잔차 평균 | **+15.93 m** |
| 잔차 표준편차 | **20.19 m** |
| 잔차 중앙값 | **+10.15 m** |
| \(\mathrm{median}(\hat{d}/d_{\mathrm{true}})\) | **1.19** |

**해석:**

1. **합성 데이터이므로** \(d_{\mathrm{true}}\)와 \(\hat{d}\) 사이에 **강한 단조 관계**(0.81)가 있다. 중간 UWB의 “상관조차 불안정” 상황과 대비된다.
2. 동시에 **거의 모든 BS에서 양의 평균 잔차**(+14~+18 m) → RTT에 **공통 오프셋·스케일 왜곡**이 있다. “거리의 순위”만 맞고 “절대값”은 틀리다.
3. 비율 중앙값 1.19 → 전역적으로 \(\hat{d} \approx 1.19\, d_{\mathrm{true}} + b\) 형태의 **아핀 왜곡**을 의심할 수 있다. **채널별·BS별 보정**이 1차 접근으로 타당하다.

### 3.2.3 기지국별 체계적 bias

**그림 삽입:** `fig07_final_per_bs_residual_mean.png`

18개 BS 모두에서 700명 평균 잔차가 **+13.8 ~ +18.0 m** (표준편차 17~25 m). 특히 모서리 BS (인덱스 0, 5, 11, 17)에서 평균 잔차·분산이 크다.

| BS id | (x, y) | 평균 잔차 (m) | \(d_{\mathrm{true}}\) 평균 | \(\hat{d}\) 평균 |
|-------|--------|---------------|---------------------------|------------------|
| 0 | (−50, 20) | +18.86 | 57.4 | 76.3 |
| 9 | (10, 0) | +13.80 | 37.3 | 51.1 |
| 17 | (50, −20) | +17.99 | 61.1 | 79.1 |

**통찰:**

- 중간 UWB의 앵커별 bias(−0.8~−3.6 m, 필터 후)와 달리, 기말은 **+10 m대의 동일 부호 bias** — “실측 하드웨어 드리프트”가 아니라 **합성 모델의 체계 파라미터**로 보는 것이 맞다.
- V15에서 Wi-Fi 캘리브가 **identity**로 선택된 것과 달리, 기말에서는 **BS별 학습 보정이 거의 필수**에 가깝다.

### 3.2.4 사용자(UE) 단위 잔차

| 지표 | 값 |
|------|-----|
| 사용자별 잔차 RMS 평균 | **24.61 m** |
| 사용자별 잔차 RMS P90 | **34.75 m** |

일부 UE는 18채널 모두에서 일관되게 \(\hat{d}\)가 크게 치우쳐 있어, **전역 아핀 한 번**으로는 부족하고 **UE별·지역별** 보정 또는 강건 융합이 필요할 수 있다.

## 3.3 Naive 측위 베이스라인: “알고리즘 없이” 어디까지 되는가

중간 보고의 **Pure Wi-Fi 1.55 m**와 비교할 수 있도록, 동일 700명에 대해 **기하 삼변만** 적용했다 (BS 좌표 `BS_positions`, 관측 \(\hat{d}_{:,u}\)).

**그림 삽입:** `fig08_final_trilat_error_cdf.png`

| 방법 | RMSE (m) | 중앙값 (m) | P90 (m) |
|------|----------|------------|---------|
| LS 삼변 (linear loss) | **25.02** | — | — |
| **Huber 삼변** (f_scale=1.0) | **19.25** | **14.51** | **28.29** |
| (참고) 중간 Pure Wi-Fi | **~1.55** | — | — |

**해석:**

1. **보정·학습 없이** 삼변만 쓰면 RMSE **19~25 m** — 기말에서 “교과서 삼변측량”만으로는 과제 목표에 미달함이 명확하다.
2. Huber가 LS보다 **약 6 m** 개선 — 중간 V15에서 **Huber·IRLS**를 고집한 것과 방향이 같다. 다만 절대 수준은 여전히 크다.
3. 중간 1.55 m와 기말 19 m는 **스케일·데이터 생성 방식**이 다르므로 **직접 비교는 unfair**하다. 기말 `report.md`에서는 **동일 RTT 입력·동일 CV**下的 Huber vs 학습 모델을 비교해야 한다.

## 3.4 중간 프로젝트 통찰과의 대조

### 3.4.1 “가공 데이터라 잘 될 것”의 정확한 의미

교수님께서 말씀하신 “가공·인공 데이터라 알고리즘만 잘 적용하면 성능이 나온다”는 관찰은 EDA와 **부분적으로 일치**한다.

| 근거 | 의미 |
|------|------|
| corr = 0.815 | **구조적 정보**가 \(\hat{d}\)에 존재 → 학습·보정 **가능** |
| Huber 19 m → (보정 후) 목표 | **여지**가 있음 — naive와 최종 사이 갭 |
| 잔차 +16 m bias | “그냥 삼변”은 **불충분** — **반드시 보정 단계** 필요 |

반면 중간처럼 **“UWB를 버리고 Wi-Fi만”** 같은 해법은不存在. 18채널 전부가 **동질 RTT**이므로, **게이트·융합·보정**을 RTT 채널에 직접 적용해야 한다.

### 3.4.2 중간 방법론의 기말 대응 (데이터 분석 관점)

| 중간에서 배운 것 | 기말 EDA가 시사하는 적용 |
|----------------|-------------------------|
| Wi-Fi 가이드 → UWB 게이트 | **가이드 없음** → 초기 \(\mathbf{p}_0\)는 Huber 삼변 또는 학습 헤드 출력 |
| 앵커별 identity 캘리브 최적 | BS별 **학습 bias/scale** (18×2 파라미터 이상) |
| OOF 기하 게이트 (V15) | 보정 후 \(\|\mathbf{p}-\mathbf{a}_k\|-\tilde{d}_k\| > \tau\) **마스킹** |
| Train CV RMSE (무결) | 700명 **K-Fold**, fold별 보정 학습 |
| 검증 100행 튜닝 | **금지** — 내부 hold-out만 |
| UWB 순차 필터 (40% 제거) | 합성 데이터 — **물리 필터 대신 잔차 기반 마스킹** |
| KNN 잔차 (V10) | 700명 규모 — **CV 없는 KNN 지양**, 소형 MLP 등 검토 |

### 3.4.3 중간에서 **못 썼던** 학습이 기말에서 열리는 이유

중간 실측 UWB에서는:

- 라벨 270행에 대해 **노이즈 패턴을 외우면** validation·hidden에 악화.
- UWB **기기 이상**이 라벨과 무관하게 섞여, 지도 학습의 **입력–출력 관계가 불안정**.

기말 합성 데이터에서는:

- **700명 GT `p`가 제공**되고, \(\hat{d}\)가 \(d_{\mathrm{true}}\)와 **상관** → \(\hat{d} \rightarrow \tilde{d}\) 또는 \(\hat{d} \rightarrow (x,y)\) **지도 학습 가정이 성립**.
- 잔차 bias가 **체계적** → **학습으로 흡수 가능**한 성분.

따라서 `train.py`에서 **PyTorch 등으로 RTT 보정·위치 회귀를 학습**하는 것은 중간의 “과적합 두려움”과 달리 **과제 의도에 부합**한다. 단, **700명 내부 CV** 없이 validation loss로 모델을 고르는 것은 중간 V12와 같은 실수가 된다.

## 3.5 알고리즘 설계에 대한 데이터 기반 함의

EDA 결과만으로 다음 **1차 연구 가설**을 세운다 (4장에서 구체화).

### 가설 H1 — BS별 아핀 보정

\[
\tilde{d}_k = \alpha_k\, \hat{d}_k + \beta_k
\]

또는 소형 공유 MLP. 18채널 독립 \(\alpha_k,\beta_k\)는 파라미터 36개로 과제 규모에 적합.

### 가설 H2 — 보정 후 강건 삼변

\[
\min_{\mathbf{p}} \sum_k \rho\big( \|\mathbf{p}-\mathbf{a}_k\| - \tilde{d}_k \big)
\]

\(\rho\): Huber (중간 V12/V15와 동일 계열). 초기값은 BS 가중 centroid 또는 H1 출력.

### 가설 H3 — 기하 게이트 (V15 이관)

보정·1차 \(\mathbf{p}\) 후, 잔차 \(|\|\mathbf{p}-\mathbf{a}_k\| - \tilde{d}_k|\)가 큰 BS는 **하드 제외** 후 재삼변. τ는 Train OOF 분위 (V15 `train_oof_gate_row_median_stats`와 동일 취지).

### 가설 H4 — End-to-end는 2단계 이후

\(\hat{d}\) 전체를 MLP에 넣어 \(\mathbf{p}\)를 직접 회귀하는 안은 **성능 상한**이 높을 수 있으나, `report.md`에서 **H1+H2 대비 공정성·해석**을 논증해야 한다. EDA상 **H2만으로 19 m**이므로, **H1+H2+H3**를 먼저 구현하고 ablation한다.

## 3.7 한계·추가 분석 예정

본 EDA는 **제공된 700명 학습 mat**만 분석하였다. 다음은 4장·구현 단계에서 수행할 예정이다.

1. **내부 hold-out** (예: 140명) — 700명에서 random split, **한 번만** 최종 성능 보고.
2. **보정 전/후** RMSE 곡선 — H1 적용 시 Huber RMSE가 19 m에서 얼마나 내려가는지.

## 3.9 요약

기말 데이터 `InF_DH_FR1.mat`은 **700명의 GT와 18 BS RTT**를 제공하는 **합성·대영역** 측위 문제이다. \(d_{\mathrm{true}}\)와 \(\hat{d}\)의 **상관 0.815**는 학습·보정의 정당성을 주지만, **+16 m급 체계 잔차** 때문에 naive 삼변(Huber RMSE **19.3 m**)만으로는 부족하다. 중간 실측 UWB의 “신뢰 불가”와 달리, 기말은 **BS별 보정 + 강건 기하 + (선택) 게이트**를 **지도 학습**과 결합할 여지가 크다. 다만 700/300 분할과 무결 튜닝 규약은 중간 V15에서 얻은 **가장 중요한 운영 교훈**을 그대로 이어받아야 한다.
